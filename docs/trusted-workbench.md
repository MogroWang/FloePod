# 安心工作台能力对照

本文把“安心工作台”建议拆成可验证的产品能力，并明确哪些内容已经由本仓库实现、哪些仍需要代码仓库之外的主体或凭据。它不是合规承诺，也不会用尚未发生的用户测试或商业合作充当完成项。

## 已实现的本地能力

| 方向 | 已实现能力 | 安全边界 |
| --- | --- | --- |
| 操作时间线与撤销 | SQLite 持久化操作、逐项成功/失败、源/目标位置、24 小时基础撤销、失败项重试、危险操作预览和“后悔按钮” | 撤销前重新核对文件身份；内容已变化时拒绝覆盖或删除；过期暂存进入系统回收站 |
| 安心模式 | 125%/150%/200% 缩放、高对比度、减少透明/动画、大点击目标、清晰文字确认、完整键盘焦点、`Alt+1`—`Alt+9`、文件/目录选择器、剪贴板文件投递、资源管理器“发送到 FloePod”、可关闭悬停弹出 | 无障碍能力免费且不依赖账号或网络；危险操作默认确认并保留当前选择 |
| 规则匣 | 八种工作流模板；按扩展名、名称、来源目录、大小和内容重复校验；安全重命名、日期子目录、SHA-256 边车文件、到期提醒、导出后清理 | 规则令牌经过路径校验；不执行脚本、不加载远程插件；管理员策略可以锁定规则 |
| 可信交接包 | 生成文件副本、`文件清单.csv`、`SHA256SUMS.txt`、`handoff.json` 和可离线阅读的 `交接说明.html`；支持包完整性复核 | 文件哈希为 SHA-256；缺失或被替换的文件会在验证结果中逐项报告 |
| 本地隐私检查与安全导出 | 检查图片 EXIF、PDF/Office/OpenDocument 元数据、文件名中的常见身份信息模式、隐藏/临时/零字节/损坏/重复文件；生成清理后的独立副本 | 全程本机处理；不修改原件；结果只作风险提示，不宣称完全匿名或行业合规 |
| 本地 OCR、全文搜索 | 文件名、PDF、Office/OpenDocument、纯文本及 Windows OCR 本机索引；标签、备注、来源、类型、日期和“上周”等可解释筛选 | 不调用在线 OCR 或语言模型；锁定匣及禁止索引的匣不会进入索引 |
| 敏感匣 | Windows EFS 静态加密、Windows Hello/系统 PIN 解锁、内存态会话、自动锁定、紧急锁定、保留期清理、导出后清理、禁用缩略图和全文索引 | 不自制加密算法、不保存密码；卷不支持 EFS 时拒绝启用；BitLocker 可作为操作系统层的附加保护 |
| 机构部署 | MSI、MSIX、NSIS 和便携包流程；可选 Authenticode 签名与签名验证；静默安装；管理员预设匣/规则/快捷键；禁止移动、必做隐私检查、数据目录白名单、保留期、审计导出和脱敏诊断包；设置导入/导出 | 机构策略来自本机 `%PROGRAMDATA%`；无远程后台、无遥测、无账号依赖；未提供证书时产物会明确保持未签名 |

## 明确不伪造的外部完成项

下列事项不能靠一次代码变更真实完成，因此不会在界面或发布说明中声称已经完成：

- Authenticode 的正式身份签名需要项目所有者购买并保管代码签名证书；流水线仅提供从机密安全注入、签名和验证的能力。
- 许可证路线（GPL、MPL、Apache 或商业双许可）会改变作者和贡献者权利，必须由项目所有者作法律决定；本变更不擅自替作者授权。
- 隐私政策、用户协议、退款规则、离线商业许可证和定价需要主体信息及法律/商业决策。
- 独立安全审查、正式 WCAG 测试报告、真实残障用户付费测试和 2—3 家机构试点必须由真实人员或机构执行，不能由自动化测试替代。
- 官网、商店上架、演示视频、培训、支持时限和公益席位属于运营交付，不会用占位数据冒充真实成果。

## 验证原则

- 基础恢复、无障碍和基本交接能力不设置付费墙，也不人为延迟。
- 默认不联网、不注册、不上传遥测；诊断包只有用户主动导出，路径默认脱敏。
- 所有清理均产生副本，所有高风险动作使用预览或确认，失败按单项记录并可重试。
- 安装包构建、哈希、签名状态和测试结果必须如实写入发布记录；缺少真实证书时不得声称“已签名”。
